Your weekly rhythm, about 15 hours

Mon2hLearn: the week's core resource
Tue2hLearn: code along with it
Wed2hPractise: exercises, no video
Thu2hBuild: start the ship
Fri2hBuild: make it work
Sat4hShip: finish, README, push
Sun1-2hReview, then post what you learned
The one ruleShip something every week. Watching tutorials feels like progress; it is not. Every week ends with one small thing you build and push to GitHub. Twenty-four weeks later, that commit history is your resume. Learn → build → push → post.

Phase 01▾

Programming foundations

Weeks 1 to 4
4 weeksZero code neededPython / Git / SQL / APIs

Every AI system you will build is software first. Four weeks of Python, Git, SQL and APIs is the floor everything else stands on - skip it and every later phase gets harder.

You are done when
  • You write a 150-line Python program without copying a tutorial.
  • You branch, commit and open pull requests without thinking.
  • You write a JOIN and a GROUP BY from memory.
  • Your FastAPI app runs locally and its /docs page works.
  • Week 01Python basics
    • Install Python and VS Code, or open Google Colab
    • Variables, numbers, strings, input and output
    • if / else, for and while loops
    • Lists, tuples, dictionaries and sets
    • Functions, arguments and return values
    • Read error messages instead of fearing them
    Ship by SundayA command-line quiz or unit converter, pushed to GitHub with a README.
  • Week 02Python for real work
    • Files, JSON and CSV
    • try / except and your own error types
    • Modules, packages, pip and uv environments
    • Classes, objects and dataclasses
    • Comprehensions, f-strings and type hints
    • Small tests with pytest
    Ship by SundayAn expense tracker CLI that saves to JSON, with tests.
  • Week 03Git, terminal and SQL
    • Terminal: navigate, pipes, environment variables
    • Git: commit, branch, merge, fix conflicts
    • GitHub: pull requests, issues, .gitignore
    • SQL: SELECT, WHERE, GROUP BY, JOIN
    • SQLite from Python, Postgres basics
    Ship by SundayA SQL analysis of a real dataset, merged through a pull request.
  • Week 04APIs and a tiny backend
    • HTTP methods, status codes and headers
    • Call REST APIs with requests or httpx
    • Keep API keys in a .env file, never in code
    • async / await basics
    • FastAPI routes, Pydantic models, /docs
    Ship by SundayA FastAPI service that wraps a public API, with two endpoints and tests.

Added, not in the original roadmap

  • Testing as a habit, not a week

    The roadmap mentions pytest once in week 2 and never returns to it. For a discipline it calls software engineering first, that is too little. Every ship from week 4 onward should arrive with tests.

    • pytest fixtures, parametrize and tmp_path
    • monkeypatch, so your tests never hit the real network
    • What is worth testing in an LLM app: the parsing, the retries, the plumbing. Not the model
    • Coverage as a hint, not a target
    DoFrom week 4 on, no ship goes to GitHub without at least three tests, one of them a failure path.
    • DOCSpytest documentationofficial
  • Working with AI coding assistants

    2026 job descriptions name this explicitly and the roadmap skips it. It is also the thing you already do every day, which makes it the cheapest credibility you own. Learn to name it properly.

    • CLAUDE.md as project memory, and what belongs in it
    • The verification loop: review every diff, never ship what you cannot explain
    • Spec-driven planning before the agent writes anything
    • Hooks for deterministic checks, and skills for repeatable workflows
    • Subagents, and when parallel work actually helps
    DoWrite a CLAUDE.md and one pre-commit hook for your capstone repo. Then write down one failure the agent produced and how you caught it. That story is an interview answer.
    • DOCSClaude Code overviewofficial docs
    • DOCSCLAUDE.md and memoryofficial docs
    • COURSEClaude Academyfree self-paced courses
Tutorial hellFinishing a 12-hour video and building nothing. Cap tutorials at half your week; the other half is your own code, with the video closed.

Phase 02▾

Data and math for ML

Weeks 5 to 6
2 weeksIntuition firstNumPy / pandas / math

Models eat data and speak in vectors. Two weeks to get fluent with NumPy and pandas, and to build intuition for the handful of math ideas that machine learning actually uses.

You are done when
  • You clean and summarise a messy CSV in pandas in under an hour.
  • You can explain a gradient and a dot product to a friend.
  • You read a distribution plot and spot outliers.
  • Week 05NumPy, pandas and plots
    • NumPy arrays, shapes, broadcasting
    • pandas: load, filter, group, merge, pivot
    • Missing values, dtypes, duplicates
    • Charts that answer one question each
    • Notebook workflow in Jupyter or Colab
    Ship by SundayAn EDA notebook on a real Indian dataset: 5 charts, 5 written findings.
  • Week 06The math you actually need
    • Vectors, dot products, matrix multiplication
    • Derivatives, the chain rule, gradients
    • Gradient descent, by hand and in code
    • Probability, conditional probability, Bayes
    • Distributions, mean, variance, sampling
    Ship by SundayGradient descent from scratch in NumPy fitting a line, with a loss plot.
Math paralysisTrying to finish a full linear-algebra course before touching ML. Learn the intuition now and go deeper only when a concept blocks you.

Phase 03▾

Classical machine learning

Weeks 7 to 9
3 weeksscikit-learnKaggle practice

Before deep learning, learn how any model learns, overfits and gets measured. These three weeks give you the vocabulary every ML and AI interview assumes.

You are done when
  • You can pick a metric for a problem and defend it.
  • You can show overfitting on a learning curve.
  • One ML app of yours runs at a public URL.
  • Week 07How machines learn
    • Supervised vs unsupervised learning
    • Train, validation and test splits
    • Linear and logistic regression
    • Loss functions and overfitting
    • Accuracy, precision, recall, F1, ROC-AUC
    • scikit-learn: fit, predict, score
    Ship by SundayA price or marks predictor with a clean split and a metrics table.
  • Week 08Trees, ensembles, clustering
    • Decision trees and random forests
    • Gradient boosting: XGBoost, LightGBM
    • Cross-validation and hyperparameter search
    • k-means clustering and PCA
    • Feature engineering and scaling
    Ship by SundayA Kaggle submission with a notebook that explains every step.
  • Week 09An end-to-end ML project
    • scikit-learn Pipeline and ColumnTransformer
    • Imbalanced classes and the right metric
    • Compare models, then study the errors
    • Save and load models with joblib
    • A small Streamlit or Gradio front end
    Ship by SundayA churn or fraud predictor with a public demo link.
The wrong metricChasing 99% accuracy on imbalanced data. Accuracy lies there - read precision, recall and the confusion matrix instead.

Transformers and LLMs

Weeks 13 to 14
2 weeksGPT from scratchOpen models

Open the black box. Build attention and a tiny GPT yourself, then learn how real LLMs are pretrained, tuned, made to reason and served.

You are done when
  • You can draw a transformer block and explain each part.
  • You can explain why temperature changes an answer.
  • You know what SFT and RLHF each add to a base model.
  • Week 13Attention and transformers
    • Tokenization and byte-pair encoding
    • Token and position embeddings
    • Self-attention and multi-head attention
    • The transformer block: residuals, layer norm
    • Decoder-only (GPT) vs encoder (BERT)
    Ship by SundayA small character-level GPT trained on text you choose, with samples.
  • Week 14How LLMs are built and run
    • Pretraining on web-scale text
    • Instruction tuning (SFT) and RLHF / preference tuning
    • Reasoning models and test-time compute
    • Sampling: temperature and top-p
    • KV cache, context windows, latency
    • Open-weight models with Hugging Face and Ollama
    Ship by SundayA comparison of 3 open models run locally on 20 of your own prompts.
The wrong goalBelieving AI engineers pretrain models. Understand the internals, then move on - your job is building with models.

Which agent framework? Pick on purpose

No frameworkLearning the basics, or one simple tool loop. Start here. LangGraphExplicit state graphs, checkpoints and human approval. OpenAI Agents SDKFew primitives: agents, handoffs, guardrails, tracing. Claude Agent SDKClaude Code's file, shell and web tools, with permissions. Google ADKGemini and Google Cloud stack, with a built-in dev UI. CrewAIQuick role-based multi-agent crews with little code. smolagentsA tiny library of code-writing agents for any model. PydanticAIType-safe Python agents with validated outputs.

Agent safety checklist

  • Least privilege: each tool gets only the access it needs
  • Ask first: a human approves anything that writes, pays or sends
  • Hard limits: cap steps, tokens and cost on every run
  • Lethal trifecta: never combine private data, untrusted content and outbound actions
  • Log everything: every tool call, with its inputs and outputs
  • Evals before trust: run real tasks, many times, before you rely on it

Fresher AI roles in India are scarce and advertise 3.5 to 7 LPA, while roles asking for three or more years pay materially better and draw far less competition. Write every application as an experienced developer moving into AI, never as a graduate entering it, and skip the internship boards entirely.

The job-ready checklist

  • Six pinned GitHub repos, each with a README, a demo and eval results.
  • One capstone with real users - even twenty people counts.
  • A one-page resume, projects first, a number in every bullet.
  • A Hugging Face profile with at least one model and one Space.
  • Ten public posts explaining what you built and what broke.
  • Out loud: RAG vs fine-tuning, agents vs workflows, how you run evals.
  • Live-code an LLM API call, parse its JSON, handle the failure.
  • Three mock interviews done, one of them a system design.
